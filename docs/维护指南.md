# 维护与更新

## 日常操作

1. 在原「音频资源库」文件夹中添加、替换或移除音频，沿用“来源 / 用途分类 / 文件”的结构。
2. 双击原文件夹中的 **更新音频库.command**。
3. 等待终端显示“发布完成”。几分钟后刷新在线目录。

想连续更新，可双击 **持续同步音频库.command** 并保持终端运行。文件稳定 15 秒后同步，两次发布至少间隔 60 秒；按 `Ctrl+C` 停止。该功能没有安装后台服务，关机、退出终端或拔出移动硬盘后不会继续上传。

## 发布了什么

- `audio/`：原始音频、原始清单与来源说明；原文件夹不被脚本改写。
- `catalog.json`：自动更新的时长、格式、来源、SHA-256 和分类统计。
- `README.md`：自动更新的仓库首页。
- Release `library`：全量 ZIP 和各分类 ZIP。链接固定，内容随更新变化。
- GitHub Pages：从 main 分支根目录发布。每次推送后自动部署，无需另行上传网页。

同步是一次发布过程，不是瞬时事务；部署与下载包更新期间可能短暂显示前一个版本。以页面内容更新时间和 ZIP 内的 SHA256SUMS 为准。

## 添加素材

支持 `.mp3`、`.wav`、`.ogg`。沿用 01–11 类目录，新增来源包应提供 `SOURCE.txt`：

```text
包名: 资源名称
来源: https://原始来源页面
作者: 作者名称
许可: 准确的许可或授权范围
许可原文: https://许可页面
```

公共音效的许可沿用各包来源记录；三个项目的课堂共享授权不自动覆盖其他新来源。新增来源请填写真实说明，不要直接标为 CC0。所有新素材请先试听、确认来源和质量。

网页保留原文件名，中文用途优先读取原项目的“音频清单.md”。公共包没有中文说明时显示原文件名，可通过目录分类及来源筛选查找。

## 命令行使用

仓库首次安装依赖：

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

需要 Git、Python 3、已登录的 GitHub CLI（`gh auth login`）。默认从 PATH 找 gh，可用 `GH_BIN` 指定可执行文件路径。

```sh
.venv/bin/python scripts/sync.py --source '/你的音频资源库路径' --dry-run
.venv/bin/python scripts/sync.py --source '/你的音频资源库路径'
.venv/bin/python scripts/sync.py --source '/你的音频资源库路径' --watch
```

只重建本地目录和下载包：

```sh
.venv/bin/python scripts/build_catalog.py
```

## 保护与故障处理

- 原路径不存在或没有音频时拒绝同步，防止移动硬盘未挂载导致误删。
- 一次移除超过 20% 且超过 20 个文件时拒绝同步。确认后才使用 `--allow-large-deletions`。
- 使用 GitHub API 上传变更文件，核对文件与目录树哈希后更新分支；本地仍保留完整 Git 版本记录。不会强制覆盖远端改动。远端和本地提交不一致时先处理差异，再重试。
- 网络中断可重新运行；下载包按内容 SHA-256 跳过已完成上传的包。
- `.DS_Store`、`._*`、隐藏文件、临时脚本和非音频/说明文件不会从源目录发布。
- 文件在复制期间仍被修改时停止，等复制完成后重试。
- 页面有更新但试听异常时，检查浏览器格式支持和网络；OGG 在部分浏览器版本中可能不可播放，仍可下载原文件。
- 仓库采用普通 Git 保存音频。单文件接近 100 MiB 或网页总资源接近 1 GiB 时，应改用 Release / 对象存储，避免继续扩大 Pages 站点。

维护脚本只会提交它管理的音频、目录索引和首页；网页样式、播放器代码修改请单独检查并提交。
